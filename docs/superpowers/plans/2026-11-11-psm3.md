# PSM-3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugin VST3/AU/Standalone "PSM-3" (Collateral Effects) che emula l'EMS VCS3 Mk I con tastiera DK1, con interfaccia che replica i pannelli originali e controllo MIDI di ogni comando.

**Architecture:** Motore DSP in C++17 puro (`Source/DSP`, namespace `psm3`) che lavora in volt reali a 4× la frequenza dell'host; ogni dispositivo è una classe testabile da sola e `PSM3Engine` li collega attraverso la matrice resistiva 16×16. Il plugin JUCE (`Source/Plugin`, `Source/GUI`) passa al motore manopole 0…10, pin e MIDI. I test del motore si compilano in locale con `clang++`; il plugin si compila solo su GitHub Actions.

**Tech Stack:** C++17, JUCE 8.0.15 (FetchContent), CMake ≥ 3.25 + Ninja (solo in CI), clang++ di sistema per i test locali, GitHub Actions `macos-15`.

**Spec:** `docs/superpowers/specs/2026-11-11-psm3-design.md`

## Global Constraints

- Il motore (`Source/DSP`) non include nessun header JUCE. Solo libreria standard C++17.
- Tutte le grandezze del motore sono in volt (`double`); alimentazioni +12 V / −9 V; 2 V p-p di Signal Output = −6 dBFS (cioè 1 V = 0,5 a fondo scala).
- Manopole: scala 0…10 come sul pannello, sia nei setter del motore sia nei parametri dell'host.
- Frequenza interna: 4× l'host sotto 88,2 kHz, 2× da 88,2 kHz in su. I test usano 192000 Hz interni.
- Nessuna allocazione, lock o I/O nel thread audio.
- Ordine di precedenza delle fonti: specifiche del manuale di servizio → manuale d'uso → schemi → letteratura.
- Riferimenti locali (non in git): `docs/reference/service/pNN.jpg` e `text.txt`, `docs/reference/user/…`. Prima di implementare un dispositivo, leggere la pagina di schema e la pagina di allineamento indicate nel task.
- Nomi prodotto: `PRODUCT_NAME "PSM-3"`, `COMPANY_NAME "Collateral Effects"`, `BUNDLE_ID com.collateraleffects.psm3`, `PLUGIN_MANUFACTURER_CODE Coef`, `PLUGIN_CODE Psm3`. Binario universale arm64 + x86_64, macOS 11+.
- Testi dell'interfaccia e documentazione utente in italiano; serigrafie del pannello in inglese come l'originale.
- Commit: messaggi in italiano, autore `-c user.name="Collateral Effects" -c user.email="noreply@localhost"`, ultima riga `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- Test locali: `scripts/test.sh` (tutti) oppure `scripts/test.sh <nome>` (uno). Devono passare prima di ogni commit.

## Review Focus

1. **Retroazione audio estrema** (es. uscita filtro nel proprio ingresso e nella propria frequenza, tutti i livelli a 10): l'uscita resta finita e il plugin non ammutolisce per sempre. → test `engine_stability` (Task 13).
2. **Cambio di patch mentre suona** (pin inseriti/tolti o preset caricato durante una nota): niente clic distruttivi, niente crash, niente nota bloccata. → test `engine_pin_swap_live` (Task 13) e `state_roundtrip` (Task 14).
3. **Note MIDI sovrapposte e fuori estensione** (legato, nota 0 e 127, note-off senza note-on, all-notes-off): nessuna nota bloccata, tensione estrapolata, gate coerente. → test `dk1_note_stack` (Task 12).
4. **Frequenze di campionamento e blocchi insoliti** (44,1/48/96/192 kHz, blocchi da 1 e da 4096 campioni, `prepare` chiamato più volte): intonazione invariata entro ±0,5 %. → test `engine_rates` (Task 13).
5. **Stato salvato sconosciuto o corrotto** (XML troncato, parametri mancanti, versione futura): si mantiene il patch corrente, nessun crash. → test `state_garbage` (Task 14).

namespace psm3 {
enum class Pin : uint8_t { None = 0, White, Red, Green };
using PinGrid = std::array<uint8_t, 256>;          // indice = riga*16 + colonna, valori di Pin
struct MatrixSolution { std::array<float, 256> t{}; std::array<bool,16> colUsed{}; std::array<bool,16> rowUsed{}; };
class Matrix {
public:
